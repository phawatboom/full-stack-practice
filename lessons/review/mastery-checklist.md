# Junior ownership checklist

Use evidence links, not only checkmarks. Mark each as **not attempted / with help / independent / needs review**. Reattempt a variation before marking a skill independent.

Add foundation/scenario scores only for work actually attempted. Link a prediction correction, a tested implementation and a technical explanation for your weakest topics. The [scenario guide](scenario-guide.md), [integrated checkpoints](checkpoints.md) and [concept map](../00-start/concept-map.md) support reassessment; they do not replace reviewed project evidence.

| Area | Evidence you should be able to produce | Status / evidence |
| --- | --- | --- |
| Workspace | Fresh setup; relevant commands; focused Git diff | |
| JavaScript | Correct immutable transforms; modules; edge cases | |
| Async | Controlled failure/race handling; no swallowed errors | |

| HTML/accessibility | Keyboard journey; labels/errors/focus/zoom | |
| CSS | Responsive layout with long/empty/error content | |
| React | Minimal state, stable identity, justified effects | |
| Browser data | Draft retention; no stale/account-inappropriate results | |
| HTTP | Trace of request/status/headers and origin rules | |
| API | Documented contract; bounded input; useful errors | |
| SQL | Relations/joins/counts; safe parameters; stable ordering | |
| Data changes | Fresh/upgrade migration; atomic conflict test | |
| Identity | Established verified session; expiry/logout behavior | |
| Authorization | Two-client direct API tests across all routes | |
| Security | Threat model and observed controls | |
| Reliability | Defined retry/idempotency policy and limits | |
| Tests | Rule/integration/browser evidence; regression fails before fix | |
| Debugging | Reproduction → evidence → cause → fix → test | |
| Performance | Representative before/after result with limits | |
| Deployment | Known release; configuration; smoke checks; restore evidence | |
| CI/dependencies | Reproducible install/checks; narrow permissions | |
| Design | Clarified brief, acceptance examples, trade-off record | |
| Edge semantics | Time/null boundaries; integration trust boundaries | |
| CS | Independent small solutions with correct complexity | |
| Communication | Reviewable submission; honest limitations and estimate | |

Review with another engineer or submit your code and evidence in chat. Do not average away an unresolved permission leak or data-loss defect. The next learning task should target the weakest demonstrated core skill, not the largest new framework.
